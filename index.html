Lesson 4: Real-Time Data Processing and Monitoring

Collecting data is only step one. This lesson covers turning raw, noisy sensor readings into meaningful information — and watching that information continuously to detect, alert, and respond to real-world conditions.

01Processing Raw Sensor Data

Why raw readings need processing

A raw sensor reading is rarely ready to use directly. It may jump around due to electrical noise, arrive in units that mean nothing to a human (like a 0–1023 ADC value), or need to be summarized across many readings instead of read one at a time.

Smoothing noisy data: the moving average filter

A single reading can spike due to noise. A moving average filter keeps the last N readings and reports their average instead of the raw value — spikes get diluted rather than trusted outright.

const int N = 5; float samples[N]; int idx = 0; float smooth(float newVal) { samples[idx % N] = newVal; idx++; float sum = 0; for (int i = 0; i < N; i++) sum += samples[i]; return sum / N; }
Key idea: a moving average trades a little bit of responsiveness for a lot of stability — the bigger N is, the smoother (but slower to react) the result.

Scaling raw values with map()

Arduino's analog pins return 0–1023 regardless of what's plugged in. map() converts that raw range into a range that actually means something — degrees, percent, volts.

int raw = analogRead(A0); // 0–1023 float voltage = raw * (3.3 / 1023.0); // 0.0–3.3 V int percent = map(raw, 0, 1023, 0, 100); // 0–100 %

Running statistics without storing everything

Min, max, and average don't require keeping every reading ever taken — only the running result updates each time a new value arrives.

float runningMax = -9999; float runningMin = 9999; float runningSum = 0; int count = 0; void update(float value) { if (value > runningMax) runningMax = value; if (value < runningMin) runningMin = value; runningSum += value; count++; } // average = runningSum / count

02Monitoring & Responding to Conditions

Threshold detection — the simplest monitor

The core of monitoring is a comparison: is the processed value inside an acceptable range? If not, trigger a response.

const float TEMP_LIMIT = 30.0; if (smoothedTemp > TEMP_LIMIT) { digitalWrite(BUZZER_PIN, HIGH); Serial.println("ALERT: temperature too high"); } else { digitalWrite(BUZZER_PIN, LOW); }

State-based monitoring (with hysteresis)

A single threshold can "flicker" if the value hovers right at the limit. Real monitors usually use multiple states — and sometimes a different threshold to enter vs. leave a state — so the system doesn't rapidly switch back and forth.

enum State { NORMAL, WARNING, CRITICAL }; State current = NORMAL; void updateState(float temp) { if (temp > 35) current = CRITICAL; else if (temp > 28) current = WARNING; else if (temp < 26) current = NORMAL; // lower re-entry point avoids flicker }

Debouncing digital monitoring signals

Digital inputs (a button, a motion sensor) can briefly flicker between HIGH and LOW during a single physical change. Debouncing ignores changes that happen too soon after the last one.

unsigned long lastChange = 0; const long debounceDelay = 50; int lastState = LOW; void checkInput() { int reading = digitalRead(SENSOR_PIN); if (reading != lastState && millis() - lastChange > debounceDelay) { lastChange = millis(); lastState = reading; // react to the confirmed change here } }

03Putting It Together

A full monitoring sketch chains everything above: collect → smooth → classify into a state → respond, with the LCD showing the current state at a glance.

void loop() { if (millis() - lastRead >= 2000) { float raw = analogRead(A0) * (3.3/1023.0) * 100; // scale to °C float temp = smooth(raw); // filter noise updateState(temp); // classify lcd.clear(); lcd.setCursor(0,0); lcd.print(temp); lcd.setCursor(0,1); if (current == CRITICAL) lcd.print("CRITICAL!"); else if (current == WARNING) lcd.print("Warning"); else lcd.print("Normal"); lastRead = millis(); } }

04Key Vocabulary

TermMeaning
ProcessingTransforming raw data into meaningful information (filtering, scaling, statistics).
MonitoringContinuously checking processed data against conditions and responding.
Moving average filterSmooths noisy readings by averaging the last N values instead of trusting one.
map()Rescales a value from one numeric range into another.
ThresholdA boundary value that separates acceptable from unacceptable readings.
HysteresisUsing different thresholds to enter vs. leave a state, to prevent flickering.
DebounceIgnoring rapid, spurious changes in a digital signal right after a real change.
